# New API entity

Follow this order. **Default reference:** pick the closest existing domain (e.g. `brand_service.go`, `brand_controller.go`, `brand_routes.go`).

## Checklist

```text
- [ ] make migrate-create name=create_{entity}_table && make migrate-up
- [ ] internal/models/{entity}_model.go
- [ ] internal/dto/{entity}_dto.go
- [ ] internal/services/{entity}_service.go
- [ ] Register in services.go AND container.go
- [ ] internal/controllers/{entity}_controller.go
- [ ] internal/routes/{entity}_routes.go + setup.go
- [ ] Swagger comments → make swagger
- [ ] go test (unit and/or tests/integration/)
- [ ] Tell frontend: restart API → pnpm api:gen
```

## Gotchas

- **No `internal/repositories/`** — GORM queries live in the service via `*gorm.DB`.
- **Register in both `services.go` and `container.go`** — forgetting either causes nil handlers at runtime.
- **Migrations: schema only** — no demo products or seed data in Goose files.
- **Never edit `docs/`** — generated by `make swagger`; gitignored locally.
- **Swagger wraps responses:** `@Success 200 {object} utils.Response{data=dto.EntityResponse}`
- **Status strings** → `internal/constants`, not literals in business logic.
- **Multi-table writes** → `db.Transaction`; async order/shipment work → `tasks.JobQueue`, not goroutines.
- **Windows migrations:** if `make migrate-up` fails, try `make migrate-up-docker`.

## Layer rule (one line)

Controller binds/validates/responds; service owns rules + DB. No logic or `gorm.DB` in controllers.

## Validate

```bash
go build ./...
go test ./internal/services/...   # or tests/integration/ with DATABASE_URL
```

For handler/Swagger details, read [references/handler-pattern.md](references/handler-pattern.md).
